Queues and jobs

Hand work to a queue and get on with the request.

  • Named queues

    Give each kind of work its own queue, with its own limits, so a flood of emails never slows invoices.

  • Priorities and delays

    Run a job now, in 30 seconds, or at a set time. Urgent jobs go to the front of the line.

  • Idempotency keys

    Attach a key to a job and duplicates collapse into one run. Retrying a request is safe.

  • Concurrency and rate limits

    Cap how many jobs run at once, and how fast they start, per queue.

Schedules

Clocks that don't drift and don't double-fire.

  • Cron and plain English

    Write 0 2 * * * or “every weekday at 9”. Nightshift shows the next five runs before you save.

  • Time zones with daylight saving

    Schedules follow the zone you choose, including the night the clocks change.

  • Overlap rules

    Skip a run, queue it, or cancel the previous one when a job is still working at the next tick.

  • Catch-up after downtime

    Choose to skip missed runs, run the latest one, or run them all in order.

Retries and workflows

Failure is a normal Tuesday. Plan for it once.

  • Retry policies

    Set attempts, backoff and a maximum wait in one place. Share a policy across queues.

  • Backoff with jitter

    Fixed or exponential delays, with random spread, so a hundred retries don't arrive together.

  • Dead-letter queues

    Jobs that run out of attempts wait for you with their payload and logs. Replay one or a thousand.

  • Long-running workflows

    Chain steps, sleep for a day, wait for an event, and resume from the last checkpoint after a deploy.

Visibility and scale

See what ran, what waited and what it cost.

  • Run timeline

    Every attempt, wait and log line for a job, on one line, in the order they happened.

  • Search across runs

    Find a job by payload, error or ID. Filter by queue, status and time.

  • Alerts that name the queue

    Get notified about failures, late jobs and growing backlogs, routed to the team that owns the queue.

  • Autoscaling on queue depth

    Workers start when a backlog builds and stop when it clears. Set a ceiling and a monthly spend cap.
