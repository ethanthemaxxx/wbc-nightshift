Enqueue

Send the job. Get on with your day.

Call enqueue from your API and respond to the user. Nightshift takes the payload, keeps its place in line and hands it to a free worker. Priorities, delays and idempotency keys come built in. Learn more

Queues with their own limits

Cap concurrency per queue so one noisy job can't starve others.

Delays and priorities

Run it in thirty seconds, or jump the line.

Idempotency keys by default

Enqueue the same job twice and it still runs once.

Instead of

  • a self-hosted queue
  • a hand-sized worker pool
  • a jobs table in your database

Schedule

Set the clock once. It keeps the time.

Write a cron expression or plain English. Nightshift fires it on time, in the time zone you pick, and never twice when two servers wake at once. Daylight saving is handled. Missed runs are your call. Learn more

  • Cron or plain English

    Type 0 2 * * * or “nightly at 2” and preview the next five runs.

  • Real time zones, real DST

    A 02:00 job in Madrid stays at 02:00 in Madrid, all year.

  • Skip, queue or catch up

    Decide what happens to runs missed during an outage.

Instead of

  • a crontab on one VM
  • a lock file to stop double runs
  • a calendar reminder to check it

Retry

It will fail. It will run again.

Set attempts, backoff and jitter. Nightshift waits, tries again, and spaces retries so a struggling API gets room to recover. Jobs that run out of attempts land in a dead-letter queue for replay. Learn more

  • Backoff with jitter

    Wait 2 seconds, then 8, then 32, so retries don't stampede.

  • Retry only what's retryable

    Retry a 503 or a timeout. Fail fast on a bad payload.

  • Dead-letter queue with replay

    Out of attempts? The job waits for you, payload and logs intact.

Instead of

  • a try/catch loop with sleep
  • a cron that re-runs yesterday's failures
  • a spreadsheet of stuck jobs

Observe

Every run, logged. Every failure, explained.

Open any job and see its payload, each attempt, the logs and how long it waited. Search across runs, filter by queue, and alert on failed runs and growing backlogs before a customer writes in. Learn more

A timeline for every job

Attempts, waits and logs on one line, in the order they happened.

Search across all runs

Find the job that failed for order 90417 without opening a terminal.

Alerts that name the queue

Get paged for the queue that is late, not the whole fleet.

Instead of

  • tailing logs over SSH
  • a dashboard nobody maintains
  • a guess about what ran last night

Scale

Busy night? More workers clock in.

Nightshift watches queue depth and adds workers when the line grows, then sends them home when it clears. You set the ceiling and the spend limit. Idle machines cost nothing. Learn more

Autoscaling on queue depth

Workers start within seconds when a backlog builds.

Hard spend limits

Set a monthly cap and jobs pause there instead of surprising you.

Run in your cloud

Keep workers in your own VPC when data can't leave it.

Instead of

  • a fixed pool of idle servers
  • a 3 a.m. scale-up script
  • a cloud bill you read after the fact
